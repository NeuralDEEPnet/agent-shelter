## Defect found and fixed

`screenResident` enriches a parked package's spec (declared tools, `registryMeta` with README and
version) but left the intake-time `fingerprint` in place. `cleanIntakeDecision` compares the stored
fingerprint against the fingerprint of the stored spec, so every clean package came back
`spec-fingerprint-mismatch` and waited for a human tap — the MCP branch already re-fingerprints from the
fetched tool list, the package branch now does the same (`src/api/services/shelter.ts`). Re-running a
fresh package (`@modelcontextprotocol/server-everything`) through the local door: screened → clean policy
**approved** → `probation` with no human involved. Regression assertion in
`scripts/verify-open-door.test.ts`.

## What the live pipeline still depends on

- A reachable model for the 12 behavioural probes and for `ask` (OpenRouter key on the workspace). Without
  it, intakes stop at `screened` with "concerns" and are held; nothing is lost, the owner desk shows them.
- The job queue (`@adaptive-ai/sdk` queue, workspace only). In a public clone screening is a no-op.
- The intake alert mail needs `SHELTER_INTAKE_ALERT_CONNECTION_TOKEN`; without it, held intakes are
  silent (`held-alert-unconfigured`) — check `/admin` or `GET /api/mpp/catalog` → `screening`.
